**Goal:** A signed-in manager says "Draft a proposal to raise UHT milk 1 L in the North to 7.25 MAD" and gets a **pending** draft back: "UHT milk 1 L in the North, 7.00 → 7.25 MAD (+3.6%). The North pricing manager can approve it on the approval screen (PP-04 §3.2)." Approving and rejecting exist only in proposals-api. There, the role, region, tier and percent decide who may approve (D-012), and an agent's token can never approve. Five milestone-6 cases join the live suite: 42 cases, three runs in a row. A live approval check proves there is no approval path without the right role and region.

**Architecture:**
- **proposals-api** is a new service with no model:
  - `POST /drafts` creates a pending draft. Only the action agent may call it.
  - `GET /proposals`, `POST /proposals/{region}/{id}/approve` and `…/reject` serve people. Callers are the live-check CLI now, and the web app in milestone 8.
  - Each route group has its own shared validator, with a different allow-list.
  - proposals-api reads the product's tier and current shelf price itself, from Azure SQL, as the user (OBO, so row-level security applies). The draft request can't carry either.
  - Role and region come from the token's `groups` claim (D-037 pattern).
  - Proposals live in Table Storage (D-010), written with the service's own identity, keyless.
- **The action agent** is a new A2A service:
  - gpt-5-mini only extracts the request: product, region, new price or percent.
  - Code calls `POST /drafts` with an OBO token and writes the reply from fixed templates, so the reply can't misstate the price, percent, status or approver (D-038).
- **The orchestrator's router** gains `action-agent` and an `approvals` route. Code answers `approvals` with a fixed pointer to the approval screen and calls no agent (A-16, A-17).
- **`shared` v0.4.0:** the `DraftRequest`, `Proposal` and `ProposalError` contracts.

## Decisions in this plan (for the owner's review)

- **D-038, the action agent extracts; code drafts and words the reply.**
  - The model fills `{is_draft, product, region, new_price, change_pct}` (structured output, reasoning low).
  - Code calls proposals-api and answers from fixed templates built from the stored proposal.
  - **Rejected:** a tool-calling agent writing its own reply. It could call the draft approved, or misstate the percent or the approver: a false result the owner won't accept.
- **D-039, proposals-api decides approvals from what it can verify:**
  - It reads tier and current price as the user (OBO → SQL, row-level security), and takes role and region from the `groups` claim (`REGION_GROUPS`: north, center, south, directors; four distinct IDs).
  - Groups vs USER_REGIONS (m3 item 5): Entra groups are the source of truth for roles. SQL's mapping must also allow the read, so any disagreement fails closed.
  - **Conservative rules where checks are missing:**
    - every price cut needs the director (PP-04 §3.5's margin-floor check needs PP-06 data);
    - fresh produce follows its tier (PP-04 §3.4's weekly repricing needs a price index check).
  - **Hard caps:** a draft over the Tier A 3% (§3.1) or Tier B 10% (§3.2) cap is refused with the clause, since nobody may approve it.
  - **Two allow-lists in one service:** two instances of the shared validator on different routes; no second token check.
  - **Known limits:**
    - approval changes the proposal's status, not the database's prices;
    - the price is the one at draft time;
    - the proposer is stored as an object ID.
- **D-035 amended:** the router has four routes: `data-agent`, `policy-agent`, `action-agent`, and `approvals` (answered by code, no agent called).

- Consumes: `DraftRequest`, `Proposal`, `ProposalError`, `Caller.groups`, `Caller.groups_overage`, `AuthMiddleware`, `current_request` (shared v0.4.0).
- Produces:
  - **`domain/rules.py`:**
    - `ProposalProblem(status, message, clause=None, matches=())` with subclasses `Forbidden` 403, `NotFound` 404, `Ambiguous` 409, `Conflict` 409, `Invalid` 422. The application layer raises them too.
    - `RegionGroups(north, center, south, directors)` and `parse_region_groups(raw: str) -> RegionGroups`. The raw form is `"north:<id>,center:<id>,south:<id>,directors:<id>"`. Exactly those four keys, four distinct `uuid.UUID` values (stored canonical lowercase); anything else raises `ValueError`.
    - `Authority(director: bool, region: str | None)`.
    - `authority(groups: frozenset[str], overage: bool, region_groups: RegionGroups) -> Authority`. Raises `Forbidden("no pricing role in your token")` on overage, or when a non-director has zero or several region groups. Directors get `region=None`.
    - `may_access(a, region) -> bool`.
    - `change_pct(current: Decimal, new: Decimal) -> Decimal`: exact, never rounded.
    - `price_after(current, pct) -> Decimal`: rounded to 0.01, `ROUND_HALF_UP`.
    - `required_approver(tier: str, pct: Decimal) -> tuple[str, str]`, returning (approver, clause):
      - `pct == 0` → `Invalid("That's no change from the current price.")`;
      - `pct < 0` → `("director", "PP-04 §3.5")`;
      - **A:** `pct > 3` → `Invalid("PP-04 §3.1 caps Tier A increases at 3%; this would be {pct:+.1f}%.", clause="PP-04 §3.1")`, else `("director", "PP-04 §3.1")`;
      - **B:** ≤ 4 → `("manager", "PP-04 §3.2")`; ≤ 10 → `("director", "PP-04 §3.2")`; else `Invalid("PP-04 §3.2 caps Tier B increases at 10%; this would be {pct:+.1f}%.", clause="PP-04 §3.2")`;
      - **C:** ≤ 8 → `("manager", "PP-04 §3.3")`, else `("director", "PP-04 §3.3")`.
    - `check_decision(a, p: Proposal, approve: bool) -> None`. Raises `Forbidden("region not allowed")` without access, and `Forbidden("needs the pricing director")` when approving a director-level proposal as a non-director. Rejecting needs region access only.
  - **`application/proposals.py`:**
    - `Product(sku, name, tier)`.
    - `PriceBook` Protocol: `async find(term) -> list[Product]` and `async current_price(sku, region) -> Decimal | None`. Both read as the current request's user.
    - `ProposalStore` Protocol:
      - `async add(p)`;
      - `async get(region, id) -> tuple[Proposal, str] | None` (the str is the ETag);
      - `async replace(p, etag)`: an ETag mismatch raises `Conflict("changed meanwhile")`;
      - `async list(regions: tuple[str, ...], status) -> list[Proposal]`.
    - `async draft(request, caller, groups, prices, store, now) -> Proposal`, steps in this order:
      1. authority;
      2. region = `request.region or a.region`; a director without a region → `Invalid("Say which region: North, Center or South.")`;
      3. `may_access` or `Forbidden("region not allowed")`;
      4. `find`: the case-insensitive exact name wins, else the single match; zero → `NotFound("no product matches")`, several → `Ambiguous("several products match", matches=names[:10])`;
      5. `current_price` or `NotFound("no current price")`;
      6. new price = `request.new_price` or `price_after(current, request.change_pct)`;
      7. `required_approver`;
      8. store a `Proposal` with `id=uuid4().hex`, `change_pct` quantized to 0.01, `status="pending"` and `proposed_by=caller.oid`.
    - `async decide(region, id, approve, caller, groups, store, now) -> Proposal`:
      - unknown → `NotFound("no such proposal")`;
      - not pending → `Conflict("already decided")`;
      - `check_decision`;
      - `replace` with the ETag.
    - `async listing(status, caller, groups, store) -> list[Proposal]`: managers get their region, directors all three; newest first, at most 100.
  - **`AzureSqlPriceBook(server, database, obo)`:** data-agent's connection pattern (OBO per query, pooling off, access token attribute 1256), parameterized queries only:
    - `find`: `SELECT sku, product_name, tier FROM dbo.dim_product WHERE product_name LIKE ? ESCAPE '\'`, with `%<term>%` after escaping `\ % _ [`;
    - `current_price`: `SELECT TOP (1) shelf_price_mad FROM dbo.fact_sales WHERE sku = ? AND region_id = ? ORDER BY sale_date DESC`. Row-level security hides other regions, so a hidden row is `None`, never a fallback.
  - **`TableProposalStore(client: azure.data.tables.aio.TableClient)`:**
    - PartitionKey = region, RowKey = id; money and times as strings;
    - `replace` uses `UpdateMode.REPLACE`, `etag=…`, `match_condition=MatchConditions.IfNotModified`;
    - `list` filters `PartitionKey eq @r and status eq @s` per region.
  - **`fakes.py`:** `MemoryProposalStore` (versioned ETags) and `FakePriceBook(products, prices)`.
  - **`create_http_app(prices, store, region_groups, draft_validator, review_validator)`:** Starlette routes with per-route `middleware=[Middleware(AuthMiddleware, validator=…)]`:
    - `POST /drafts` (draft validator) → 201 `Proposal`;
    - `GET /proposals?status=pending|approved|rejected` (default `pending`) → 200 `{"proposals": [...]}`;
    - `POST /proposals/{region}/{proposal_id}/approve` and `…/reject` → 200 `Proposal`.
    - Region not in N/C/S, or an ID not matching the pattern → 404 `no such proposal`.
    - Bodies over 4 KB → 413; an invalid draft → 400 `{"error": "invalid draft"}`. Validation details aren't echoed.
    - `ProposalProblem` → its status, with a `ProposalError` body.
  - **Azure settings, no defaults:** `TENANT_ID`, `CLIENT_ID`, `AZURE_CLIENT_ID`, `DRAFT_CALLERS`, `REVIEW_CALLERS`, `REGION_GROUPS`, `SQL_SERVER`, `SQL_DATABASE`, `TABLE_ENDPOINT`, `TABLE_NAME`.

  - **`Proposals` Protocol:** `async draft(request: DraftRequest) -> Proposal`. A non-201 reply raises `DraftRejected(status, ProposalError)`.

    - Any other failure raises.
  - **`async draft_reply(question, extractor, proposals) -> AgentReply`.** Money passes through `Decimal(str(round(x, 2)))`. Cases, in order:
    1. `is_draft` false → "I can only draft price-change proposals. Approving, rejecting and listing them happen on the approval screen."

    3. Draft created → `wording.drafted(p)`, `citations=[p.clause]`.
    4. 403 → "You can draft proposals only for your own region.", `refusal="no_access"`.
    5. 404 `no product matches` → "No product matches that name.", `no_data`.
    6. 404 `no current price` → "No current price is recorded for that product in the {Region}.", `no_data`.
    7. 409 `several products match` → "Several products match: {a, b}. Which one?"
    8. 422 → the error text, `citations=[clause]` if any.
    9. Anything else raises.
