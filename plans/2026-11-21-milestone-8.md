## Global Constraints

- **Pins exactly as in the Tech Stack.** `package-lock.json` is committed, and CI uses `npm ci`. Python repos follow milestone 7's rule: bump, then `uv lock`, then `uv lock --check`.
- **No account-specific value in the public `web` repo** (D-026): tenant, client IDs, URLs and scopes come from `web/.env`, written by `infra/scripts/web-env.sh` and gitignored. They are public once built into the bundle, as SPA settings always are, but never in the repo.
- **The SPA has no secret:**
  - it's a public client (auth code + PKCE);
  - its registration has no password or certificate, and `entra-apps-check.sh` asserts that;
  - the Static Web Apps deployment token is fetched with `az staticwebapp secrets list` inside `deploy-web.sh`, passed straight to the deploy command, and never printed, written or committed.
- **Every service still checks every token.** The web app's client ID joins the orchestrator's `ALLOWED_CALLERS` and proposals-api's `REVIEW_CALLERS`, never `DRAFT_CALLERS`, so the browser can't draft directly.
- **CORS:**
  - `ALLOWED_ORIGINS` lists exact origins: the Static Web App's, and `http://localhost:5173` for local development; never `*`;
  - no credentials mode: bearer tokens, not cookies;
  - methods `GET` and `POST`; headers `Authorization` and `Content-Type`;
  - CORS is a browser convenience, not a security boundary: the token check still decides.
- **Text only:** answers, citations, product names and errors render as React text, never through `dangerouslySetInnerHTML`.
  - CSP: `default-src 'self'; script-src 'self'; style-src 'self'; connect-src 'self' https://login.microsoftonline.com https://*.azurecontainerapps.io; frame-ancestors 'none'; base-uri 'self'; form-action 'self'`.
  - Also `X-Content-Type-Options: nosniff` and `Referrer-Policy: no-referrer`.
- **Never log tokens, questions or answers,** in the browser console or in the services.
- **Pushes and Azure changes:** the owner's approval of this plan covers every push and tag, and Tasks 4–5's Azure/Entra changes, including one Static Web App (Free, $0) and one app registration. It also covers rejecting the pending *test* drafts left by milestones 6–7's runs, as the director, with `clear_drafts.py`.
- **Commit messages** end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Azure and MSAL commits carry the Learn URLs read. Stage explicit paths. Lint and tests gate every commit in the same command chain.

## Decisions in this plan (for the owner's review)

- **D-042: the web app.**
  - A public SPA client on Static Web Apps Free in West Europe; MSAL redirect sign-in, tokens in `sessionStorage`; one token per service.
  - Build-time settings from `web/.env`.
  - CORS in the two browser-facing services (app level, so it's unit-tested), not at the ingress.
  - The deployment token is fetched at deploy time and never stored.
  - **Rejected:**
    - popup sign-in: blocked by many browsers, awkward on phones;
    - `localStorage`: tokens survive the tab, a longer exposure;
    - Static Web Apps' built-in auth: it signs users into the static site, not our APIs, and would add a second identity path;
    - a GitHub secret holding the deployment token: a stored secret (the token-free GitHub OIDC path comes with milestone 10's deploys).
- **No approve buttons hidden by role.** The browser doesn't know your role for certain, and proposals-api decides anyway. Every pending proposal shows Approve and Reject, and a refusal is shown in plain words ("Only the pricing director can approve this one").
- **Regression check: one full live run (53 cases) instead of three.** The services change only by CORS headers and one error mapping, which can't change an answer; one run costs about $0.70 against $2 for three. Say "three" if you want the full gate.

## Review Focus

1. **Text from an agent or a proposal runs as HTML** (an answer or product name containing `<img src=x onerror=…>`). The owner expects it shown literally.
   - `test_an_answer_is_shown_as_text_never_as_html`;
   - `test_proposal_fields_are_shown_as_text`;
   - the CSP header, asserted in `test_the_static_web_app_config_sets_the_csp`.
2. **A token goes to the wrong service** (scopes swapped: the orchestrator's token sent to proposals-api). The owner expects each call to carry its own service's token, and the services to reject a wrong one (they check `aud`): `test_each_call_asks_for_its_own_services_scope`.
3. **The sign-in expires mid-session** (silent renewal fails with interaction required). The owner expects a redirect to sign in, not a broken page or a loop: `test_an_interaction_required_error_redirects_to_sign_in`.
4. **A conversation ends or belongs to someone else** (a 404 after 7 days, or after switching accounts in the same tab). The owner expects a fresh start, said plainly, and nothing left from the previous account: `test_a_404_starts_a_new_conversation`, `test_signing_out_clears_the_conversation`.
5. **Approve is clicked twice, or the list is stale** (someone else decided it). The owner expects one decision and an honest refresh.
   - `test_a_decision_disables_its_buttons_until_it_returns`;
   - `test_a_409_refreshes_the_list`;
   - proposals-api's 409 already guards the second decision.
