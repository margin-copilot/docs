# Milestone 9: Tracing, Alerting and Cost per Question Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One trace per chat turn across every service shows where the time goes. Alerts fire on failures, slowness, security signals, crash loops and runaway model use. Every eval run reports time and cost per question. Then a measured latency baseline names what to fix first.

**Outcome (2026-11-23):** done. One trace per chat turn across every service, with no content (a test per service; a live query over every table found 0 rows). The live run passed 54/54 and reported time and cost per question: average 16.9 s, $0.0047 a question, $0.25 in all. The six alerts that can be drilled fired in drills. Final versions: shared `v0.5.0`, orchestrator `v0.7.0`, data-agent `v0.3.0`, policy-agent `v0.1.6`, action-agent `v0.1.3`, proposals-api `v0.3.0`. The baseline: `research/2026-11-latency-baseline.md`. Deviations, from the run ledger:
- **Prices** come from the meters Cost Management bills (input 0.25, cached input 0.025, output 2.00 USD per million tokens). The retail API lists only "pp" meters, and cached input, 80% of input tokens, is priced at its own rate.
- **`ALERT_EMAIL`** defaults to the budget alerts' contact.
- **The live checks and drills found two bugs:**
  - span labels arrive as `"True"` and KQL's `==` is case-sensitive, so a cold turn counted as warm (`=~`, `!~` now);
  - rejected tokens diluted `chat-failing` below its threshold (signed-in turns only now).
- **No `data_agent.margin` span:** Agent Framework's tool span times it. proposals-api's span is `proposals_api.sql`, around both of its queries.
- **`CHAT_P95_SECONDS` stays 120:** warm p95 54–57 s, slowest warm turn 88 s.

- **Every Python service** exports OpenTelemetry traces and metrics to one workspace-based Application Insights, keyless:
  - the app's managed identity holds Monitoring Metrics Publisher;
  - local (key) auth is off.
  - The setup lives once, in `shared` (`margin_copilot_shared.telemetry`).
- **What a trace shows:**
  - incoming requests come from the generic ASGI middleware, which reads an incoming `traceparent`;
  - outgoing httpx calls, A2A hops included, come from the distro's bundled httpx instrumentation;
  - Azure SDK calls (Table Storage, AI Search, Foundry) come from the distro's `azure_sdk` instrumentation;
  - model calls come from Agent Framework's `enable_instrumentation(enable_sensitive_data=False)`, as `chat <model>` spans with token counts;
  - our own named spans cover routing, each agent, composing, SQL connect and query, policy clauses and the price book.
- **No content in telemetry:** no prompts, answers, SQL text, SQL rows or tokens. A unit test per service and a live query prove it.
- **Logs:** the services export no OpenTelemetry logs. Container console and system logs reach the same Log Analytics workspace through the environment's `azure-monitor` destination and a diagnostic setting, which is keyless.
- **Alerts (Bicep, infra repo):**
  - five log search rules at 15-minute frequency;
  - a `RestartCount` metric alert per app;
  - Failure Anomalies (smart detection);
  - one email action group, to `ALERT_EMAIL`.
- **Dashboard:** a Grafana dashboard ("Chat latency") in the Azure portal's free Grafana, deployed as code.
- **Evals:** the live runner sends a `traceparent` per case. After the run it queries the workspace by trace ID and prints, per question: total time, time per step, model calls, tokens and cost.

## Global Constraints

- **Telemetry carries no content:**
  - no question, answer, prompt, instructions, tool arguments or results;
  - no SQL text, SQL rows, tokens or `Authorization` headers.
  - Counts, durations, labels (route, agent, refusal) and error types only.
- **Keyless export:**
  - `credential=ManagedIdentityCredential(client_id=AZURE_CLIENT_ID)`;
  - the component has `DisableLocalAuth: true`;
  - the connection string is configuration, not a secret ("Ikey unique identifiers aren't security tokens").
- **Telemetry never breaks a request or a start:** a failed setup logs one warning and the service runs untraced.
- **No connection string means no telemetry:** fake mode, tests and CI never export.
- **Sampling 100%** (`sampling_ratio=1.0`): every eval case's trace must exist for the cost report.
- **Account-specific values are configuration (D-026):**
  - `ALERT_EMAIL` (already in infra's `.env`);
  - `LOG_DAILY_CAP_GB`, `LOG_RETENTION_DAYS`, `CHAT_P95_SECONDS`, `TOKEN_CEILING_PER_HOUR` in `infra/.env.example`;
  - `MONITOR_WORKSPACE_ID`, `MODEL_INPUT_USD_PER_MTOK`, `MODEL_OUTPUT_USD_PER_MTOK` in `evals/.env.example`.
- **Names:** `<prefix>-logs` (workspace), `<prefix>-insights` (component), `<prefix>-alerts` (action group, short name `margin`), `chat-latency` (dashboard).
- **Pins:**
  - azure-monitor-opentelemetry 1.8.12, opentelemetry-instrumentation-asgi 0.66b2, azure-monitor-query 2.0.0;
  - no `microsoft-opentelemetry`;
  - no `opentelemetry-instrumentation-starlette` (untested on Starlette 1.x);
  - no openai instrumentation (duplicate chat spans).
- **Versions:** shared `v0.5.0`; orchestrator `v0.7.0`; data-agent `v0.3.0`; policy-agent `v0.1.6`; action-agent `v0.1.3`; proposals-api `v0.3.0`.

## Cost

- **Ingestion:** about 40 spans of about 1 KB per chat turn, so a 54-case run is about 3 MB. The first 5 GB a month are free, then $2.76/GB. The workspace has a daily cap (`LOG_DAILY_CAP_GB`, default `0.2`). Included retention is 31 days, or 90 for App Insights data.
- **Alerts:**
  - five log rules at 15 minutes: $0.50 each, so **$2.50 a month**;
  - metric alerts: free (first 10 series);
  - email: free (first 1,000);
  - `ALERTS_ENABLED=false` disables every rule, and disabled rules cost nothing.
- **Grafana dashboards in the portal:** free. App Insights and the workspace have no standing fee.
- **Live work:**
  - one full run, about $0.50;
  - drills and the baseline, about 15 questions, about $0.25.
- **Spend so far:** about $10–11 of the $20 budget (Cost Management lags a day).

## Decisions in this plan (for the owner's review)

- **D-043: observability.**
  - Application Insights + OpenTelemetry (Azure Monitor distro), keyless, no content in telemetry, 100% sampling.
  - Container logs through the environment's diagnostic setting.
  - Grafana in the portal.
  - Five log rules, restart metric alerts and Failure Anomalies, all to one email action group.
  - **Rejected:**
    - Langfuse: its value is prompt capture, which our rules forbid; it needs an API key and is an outside service;
    - Grafana Cloud: outside service plus a key;
    - Azure Managed Grafana Standard: paid, for what the portal gives free;
    - `microsoft-opentelemetry`: pulls the Agent Framework meta package and extra instrumentations;
    - a synthetic uptime test: a chat turn needs an MFA sign-in, and a ping keeps apps awake against scale to zero;
    - Foundry's Tracing page connection: an API-key connection that stores the connection string, while App Insights already shows the same spans.
- **One full live run, not three.** Telemetry doesn't change answers. Say "three" if you want the full gate.
- **The drills briefly break the live system on purpose:**
  - the data agent's revision is deactivated for about 5 minutes;
  - a proposals-api revision that fails at start is deployed, then replaced.
  - Nobody else uses the system.
- **The dashboard's definition uses a preview API version** (`2025-09-01-preview`; the parent resource is stable). If it fails, the JSON stays in the repo and is imported in the portal (New > Import).
- **The latency fixes are not in this milestone.** It ends with a measured breakdown and a ranked list; the fixes get their own plan.

- Produces (in `margin_copilot_shared.telemetry`):
  - `configure_telemetry(service: str, env: Mapping[str, str], configure: Callable[..., None] = configure_azure_monitor) -> bool`
    - `True` when telemetry was set up.
    - Without `APPLICATIONINSIGHTS_CONNECTION_STRING` it returns `False` and calls nothing.
    - Otherwise:
      - sets `os.environ["OTEL_LOGS_EXPORTER"] = "none"` (no log export);
      - calls `configure(connection_string=…, credential=ManagedIdentityCredential(client_id=env["AZURE_CLIENT_ID"]), resource=Resource.create({"service.name": service}), sampling_ratio=1.0)`.
    - Any exception is caught, logged once as a warning (type only) and returns `False`.
  - `instrument_app(app: ASGIApp) -> ASGIApp`: `OpenTelemetryMiddleware(app, exclude_spans=["receive", "send"], server_request_hook=_mark_cold_start)`.
    - `_mark_cold_start` sets `margin.cold_start=True` on the first non-`OPTIONS` HTTP request of the process only.
  - `span(name: str, **attributes: str | int | float | bool) -> AbstractContextManager[Span]`: `start_as_current_span` on the tracer `margin_copilot`. Attribute keys use the `margin.` prefix.
- Produces (in `margin_copilot_shared.testing.telemetry`):
  - `recorded_spans() -> AbstractContextManager[list[ReadableSpan]]`: an SDK `TracerProvider` with an `InMemorySpanExporter`, installed globally once per process and cleared on entry.
  - `texts_in(spans: Sequence[ReadableSpan]) -> str`: span names, attribute values and event attribute values, joined, for asserting absence.
