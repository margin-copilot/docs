**Goal:**
- **Several agents, one answer.** A signed-in user asks something that needs more than one agent ("Was the North flour increase in February 2026 allowed?"). The data agent and the policy agent both answer, and the orchestrator writes one answer that only uses their facts and numbers, with their citations.
- **Scope:** out-of-scope questions get a short decline, with no agent called.
- **Conversations:** a conversation can be continued with follow-ups ("And in September?"), and only by its owner.
- **Done when:** milestone 7's cases pass with every earlier one: 52 live cases, three runs in a row.

**Architecture:**
- **The router plans** (D-040). One gpt-5-mini call returns `{route: agents|approvals|out_of_scope, agents: [...]}`.
  - Code calls the chosen agents concurrently over A2A, with a fresh OBO token each, as today.
  - **One agent:** its reply passes through unchanged, as in milestones 4–6.
  - **Several agents:** a composer call writes one answer from their replies. Code checks that every number in it appears in a reply or in the question, retries once with the ungrounded numbers named, and otherwise falls back to the replies stitched together.
  - Citations, `agents` and `refusal` are set by code.
  - The action agent runs only when it's the sole choice: no draft as a side effect of a question.
- **Conversations** (D-041):
  - Turns live in Table Storage's `conversations` table, with PartitionKey = the owner's `oid` from the token. Another user's conversation can't be read by construction: it's not found.
  - The last 10 turns feed a condenser call that rewrites a follow-up into a standalone question. Agents stay stateless.
  - Conversations expire 7 days after their first turn.
  - `/chat` takes an optional `conversation_id` and always returns one.
- **Evals:**
  - 9 milestone-7 cases join the live suite.
  - The conversation-hijack case (A-21) runs in CI on fakes.
  - A live conversation check proves follow-ups and ownership on Azure.

**Interfaces:**

    - Numbers are found with `(?<![\d.])(\d+(?:\.\d+)?)` and compared as `Decimal` values, ignoring `%`.
    - It returns the answer's numbers, as written, that appear in no source.
  - **`domain/replies.py`:**
    - `combined_citations(replies: Sequence[AgentReply]) -> tuple[str, ...]`: first-seen order, no duplicates, at most 12.
    - `combined_refusal(replies) -> Refusal | None`: `None` if any reply has no refusal; else `no_access` if any reply has it; else `no_data`.
    - `stitched(named: Sequence[tuple[str, AgentReply]]) -> str`: `"From the sales data: …"` for the data agent and `"From the policies: …"` for the policy agent, joined by a blank line.
  - **`application/ask.py`:**
    - `Plan(kind: Literal["agents","approvals","out_of_scope"], agents: tuple[str, ...] = ())`.
    - `to_plan(route: str, agents: Sequence[str]) -> Plan`:
      - removes duplicates, in the order data, policy, action;
      - drops `action-agent` when any other agent is listed;
      - `route == "agents"` with no agents raises `AgentUnavailable("router", "no agent chosen")`.
    - `Router.route(question) -> Plan`.
    - `Composer` Protocol: `async compose(question, named: Sequence[tuple[str, AgentReply]], ungrounded: Sequence[str] = ()) -> str`.
    - `OUT_OF_SCOPE_ANSWER = "I can only help with Riad Market's pricing, margins, promotions, products and policies."`
    - `async ask(question, router, agents, composer) -> ChatReply`:
      - `approvals` → `APPROVALS_ANSWER`, as in milestone 6;
      - `out_of_scope` → `ChatReply(OUT_OF_SCOPE_ANSWER, "out_of_scope", (), ())`;
      - one agent → passed through unchanged;
      - several → `asyncio.gather`. If every reply refused: `stitched`, with `combined_refusal`. Otherwise compose; if `ungrounded_numbers` isn't empty, compose again with them; if it's still not empty, use `stitched`. Citations come from `combined_citations`, and refusal is `None`.
  - **`FoundryComposer(client, limit: float = 30)`:** structured `{answer: str}` (≤ 4,000 characters), reasoning medium, no tools, `asyncio.timeout(limit)` → `AgentUnavailable("composer", …)`. Also `FakeComposer`.

  - `create_http_app(router, agents, composer, …)`: the rest of the signature arrives in Task 2.
